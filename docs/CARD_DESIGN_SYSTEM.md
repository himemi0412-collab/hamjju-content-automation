# 카드뉴스 디자인 시스템 분리 계약

## 경계

`app/card_design_system.py`는 카드 디자인 전용 계약이다. 현재 운영 파이프라인에서 import하지 않는다. 본문 생성·QA·canonical hash·Notion handoff·네이버 브라우저 작업자·Windows 예약 작업을 바꾸지 않으며, 이 모듈이 실패해도 기존 기준 태그로 즉시 복구할 수 있다.

현재 운영의 실제 카드 합성은 `app/photographic_cards.py`의 고정된 Pillow 레이아웃에서 한다. 그 코드는 1080×1080 결과물을 만들고 한글을 배경 생성 뒤에 합성한다. 기존 계약 문서에는 1254px 표기도 있으나, 안정 기준은 실제 렌더러와 테스트가 확인하는 1080px를 따른다. 기존 자동화 동작을 바꾸지 않기 위해 이 불일치는 운영 경로에서 수정하지 않았다.

## 고정 70%

- 1080×1080 정사각형, 32px 이상 안전 여백
- cover → flow → comparison → checklist → decision의 다섯 역할과 순서
- 카드 역할마다 코드에 등록된 배치 ID만 사용하며 AI가 좌표를 제출할 수 없음
- 사진·삽화·도식 안에 텍스트를 생성하지 않고, 정확한 한글은 별도 합성
- 제목/본문 글꼴 역할과 허용 글자 크기 범위
- 텍스트 영역의 안전 여백 및 겹침 금지
- 허용 팔레트 외 색상과 허용되지 않은 요소 거부
- 게시/예약 발행은 디자인 시스템의 책임 밖

고정 규칙은 정규 JSON SHA-256으로 매니페스트에 묶는다. 규칙이 달라지면 과거 매니페스트는 검증에 실패한다.

## 변형 30%

AI가 고르는 값은 승인된 팔레트, 카드 역할별 사전 등록 배치 ID, 매체(photo/illustration/diagram), 크롭 프리셋, 강조 대상뿐이다. 좌표·캔버스·글꼴·글자 크기·역할·QA 기준 변경은 선택 입력으로 허용하지 않는다. 모르는 선택값은 기본값으로 조용히 대체하지 않고 실패시킨다.

## 독립 디자인 QA와 복구

디자인 QA는 카드 1~5 각각 PASS/FAIL, 이유, 재시도 가능 여부를 받는다. 실패 이유가 없거나 카드별 결과가 중복·누락되면 계획을 만들지 않는다. 재시도 대상은 실패한 카드 중 재시도 가능한 카드에 한정하며 카드당 최대 2회다. 통과한 카드의 SHA-256이 달라지면 선택 복구 검증을 실패시킨다. 기존 본문/카드 품질 QA는 계속 필수이고 이 모듈은 이를 대체하거나 낮추지 않는다.

## 적용 상태

이 단계는 계약·검증·테스트만 별도 모듈에 구현했다. 아직 제작 파이프라인에 연결하지 않았다. 운영에서 새 레이어를 사용하려면 별도 검토 가능한 변경으로 renderer adapter에 연결하고, 전체 회귀 테스트와 실제 카드 시각 QA를 다시 통과시켜야 한다. 현재 stable baseline의 원고·QA·hash·handoff·네이버 저장 흐름은 그대로 둔다.
