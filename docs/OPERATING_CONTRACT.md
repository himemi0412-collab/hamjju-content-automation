# 햄쮸 콘텐츠 자동화 운영 계약

계약 ID: `HAMZZU_OPERATING_CONTRACT_V1`

자동화마다 다른 기억을 갖는 문제를 막는 단일 운영 기준이다. 프로그램이 읽는
`config/operating_contract.yaml`이 정본이며, 이 문서는 사람이 읽는 설명본이다.
CI 검사는 워크플로 일정과 계약 파일이 달라지면 실패한다.

## 실행 환경별 단일 소유권

| 환경 | 유일한 역할 | 하지 않는 일 |
|---|---|---|
| GitHub Actions | 조사, 원고·대본, 카드, 이미지, 음성, 영상, 독립 QA, Notion 전달 | 네이버 편집기 조작, YouTube 업로드, 공개 발행 |
| Notion | 정본 파일, 버전, 해시, 상태 인수인계 | 콘텐츠 생성, 플랫폼 공개 |
| 로컬 브라우저 작업자 | `네이버 저장 요청` 블로그의 임시저장과 목록 재열람 검증 | 원고 수정, 카드 재생성, 쇼츠 제작, 공개 발행 |
| 사용자 | 최종 검토와 공개 결정 | 자동화가 대신 결정하지 않음 |

## 채널별 완료 경계

### 네이버 블로그

GitHub의 제작 완료 조건은 원고와 카드 5장의 독립 QA, Notion 첨부·재조회, 원고/카드 해시 기록, `READY_FOR_NAVER_DRAFT`, 상태 `네이버 저장 요청`이다. 이것은 업무 완료가 아니다.

로컬 브라우저 작업자는 같은 원고 ID·버전·해시와 카드 5장을 확인한 뒤 네이버에 임시저장하고, 임시저장 목록에서 다시 열어 제목·본문·이미지 5장이 일치할 때만 Notion을 `임시저장 완료`로 바꾼다. 공개와 예약발행은 금지한다. Notion 상태가 완료의 단일 정본이며 GitHub Actions는 요약을 쓰기 전에 해당 페이지 상태를 최대 15분간 확인한다. 시간 초과와 조회 실패는 완료가 아니다.

### 삐죽이·일본 쇼츠

완료 조건은 계정별 대본, 고정 음성, 실제 음성 길이 기반 장면표, 이미지·자막·MP4 생성, 독립 QA와 1080×1920 영상/음성 스트림 검증이다. 자동 YouTube 업로드는 하지 않는다.

## 복구 원칙

- 한 콘텐츠 버전은 한 환경만 수정한다.
- 원고 또는 자산 해시가 달라지면 덮어쓰지 않고 `MANUAL_EDIT_CONFLICT`로 중단한다.
- 실패한 단계의 검증된 파일을 보존하고 그 단계부터 재개한다.
- 한 채널의 실패를 다른 채널 성공으로 숨기지 않는다.
- GitHub Actions 결론과 실제 업무 결과를 별도 상태로 보고한다. 네이버는 임시저장 목록 재확인, 쇼츠는 MP4 실파일과 QA를 완료 기준으로 삼는다.
- 외부 API·인증·브라우저 장애는 실패 이유를 남기고 대기하며 새 콘텐츠를 중복 생성하지 않는다.

## 예약

- GitHub: 매일 10:00 KST 블로그 제작, 매일 21:00 KST 쇼츠 제작
- 로컬 브라우저 작업자: 네이버 임시저장과 목록 재열람 확인만
- Codex `automation`: 주간 키워드 선별만
- Codex `start`: 아침 START 브리핑만

테스트용 임시 cron은 운영 워크플로에 남기지 않는다.
